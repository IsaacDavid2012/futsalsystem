Demo payment cards for testing the FutsalHub booking system

Makeshift Payment Gateway

The FutsalHub system includes a demo payment gateway that simulates payment processing. This allows you to test the complete booking flow without connecting to a real payment processor.

Important: This is a demonstration system. No real charges will be made. All payment processing is simulated for testing purposes only.

Features:

  • Demo payment capture for any entered card number
  • Realistic payment processing delays (1 second)
  • Generates unique transaction IDs for each payment
  • Stores card number, CVV, and expiry fields for simulation
  • Full refund simulation on booking cancellation
  • Database integration for payment history

Test Card Numbers

Enter any card number for the demo. The system keeps the card number, expiry date, and CVV for simulation.

  • Expiry: Any date you want to store
  • CVV: Any 3-digit number
  • Cardholder Name: Your name
Example: use something like 2342 3423 4234 1223 or any other number string you want to keep in the demo record.

How Payment Processing Works

Payment Flow:

  1. User fills booking form with court, time, and personal details
  2. Payment gateway captures the entered card number, expiry date, and CVV
  3. Payment is simulated (1 second delay for realism)
  4. Unique transaction ID is generated (format: TX_XXXXXXXX)
  5. Booking is created in database with payment status
  6. Payment record stored with transaction details
  7. Confirmation shown to user with transaction ID

Refund Simulation:

When you cancel a booking from "My Bookings" page:

  • If cancelled 24+ hours before: Full refund (100%)
  • If cancelled 2-24 hours before: Partial refund (50%)
  • If cancelled <2 hours before: No refund (0%)

Backend Implementation

The payment gateway is implemented as a modular utility that can be easily replaced with a real payment provider:

// File: src/utils/paymentGateway.js const processPayment = async (options) => { const { amount, cardNumber, cardholderName, expiryMonth, expiryYear, cvv, currency = 'USD', } = options; // Captures the entered demo card details // Checks that required fields exist // Returns transactionId and payment status }; const processRefund = async (options) => { const { originalTransactionId, amount, reason, } = options; // Simulates refund processing // Returns refundId and status };
To integrate with a real payment provider:
  • Replace the mock implementation in paymentGateway.js
  • Add API credentials to environment variables
  • Update capture and storage logic to provider's requirements
  • No changes needed to frontend or routing logic

Testing Checklist

Test Scenarios:

  • Successful Booking - Use any card number, complete booking
  • View My Bookings - Check transaction details and payment status
  • Full Refund - Cancel a booking 24+ hours before time
  • Partial Refund - Cancel a booking 2-24 hours before
  • No Refund - Cancel a booking less than 2 hours before
  • Admin Overview - Check revenue and utilization metrics
